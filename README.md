# OpenCode（fnOS）— OpenCode for fnOS

**中文** | [English](README.en.md)

在飞牛 fnOS 上一键运行开源 AI 编程智能体 **OpenCode**：装完就是后台服务，从飞牛桌面点开，让 AI 在服务器上读代码、改文件、跑命令、执行测试，全程浏览器操作，不用碰命令行。

本仓库是 [OpenCode](https://github.com/anomalyco/opencode)（作者 OpenCode contributors）在飞牛 fnOS 上的**第三方非官方封装**，收录 FPK 打包脚本、Go 网关、安装/升级/卸载脚本与适配说明（对应源码目录：`opencode_all_<版本>`）。

> **安装前先读**：[二、说明](#二说明) 第 1 节「现阶段缺陷与风险」——那里写的是这个版本目前**做不到、做不好、以及可能带来的风险**，比功能列表重要。

## 一、应用性质

1. 本应用（appname = `opencode`，显示名「OpenCode」）是开源项目 OpenCode（<https://github.com/anomalyco/opencode>）在飞牛 fnOS 上的**第三方非官方封装**，由社区开发者自行打包分发，与飞牛官方（广州铁刃智造技术有限公司）及上游项目团队均无任何隶属、授权或合作关系。
2. 包内 `opencode-linux-x64` / `opencode-linux-arm64` 为**上游官方发布的原版二进制**（取自官方 npm 平台分包），本项目**不修改、不重新编译、不拆分其源码**；飞牛适配全部由包外层的自研脚本与 Go 网关完成。
3. 本应用**只提供运行环境与访问接入**，**不内置任何模型、不内置任何 API Key、不代收任何费用**。使用 AI 功能需自行填写模型服务商的 API Key，或接入本地 Ollama / vLLM 等 OpenAI 兼容端点。
4. 应用本体**完全免费、开源、非商业**，不收取任何费用，不通过任何组件盈利；使用第三方模型服务产生的费用由模型厂商直接收取，与飞牛官方、上游团队及本打包者无关。
5. 一个安装包同时支持 x86_64 与 ARM64，安装时按设备架构自动选择对应二进制，无需分开下载。
6. 服务进程以专用低权限系统用户 `opencode-agent` 运行，**不使用 root**；文件读写仅限应用数据区内的项目目录。

> 本应用通过飞牛统一网关访问（应用中心点开即为 `/app/opencode`，TLS 由网关终结），**不监听任何对外 TCP 端口**，也不启用任何公网穿透 / 隧道功能。

## 二、说明

> 本章第 1 节写的是这个版本**现阶段已知的缺陷、限制与风险**，装之前请先读完——尤其是「使用风险」和「无多用户隔离」两条；其余小节按安装、访问、配置的顺序展开。

### 1. 现阶段缺陷与风险

#### 1.1 功能限制

1. **无多用户隔离**：应用是**单实例**运行，所有能登录飞牛账号的人共用同一实例、同一项目目录、同一份模型配置，**会话列表互相可见**。多人共用一个 NAS 时，请自行约定使用范围，或只授予可信账号。
2. **项目目录固定**：固定在应用数据区内的 `@appdata/opencode/projects`，安装向导**不提供自定义路径**；想换位置只能自行迁移文件并手工调整，属非官方支持范围。
3. **仅 x86_64 / ARM64**：只提供 Linux 二进制，没有 32 位版本，也没有 Windows / macOS 客户端形态；其它架构在安装前检查阶段会被直接拦下。
4. **不内置模型、不内置 Key、不提供网络代理**：首次使用必须自备模型 API Key 或本地端点。NAS 不能出网时，在线模型目录为空、云端模型不可用。
5. **单机单实例**：不支持多机集群，也不支持把会话迁到另一台 NAS 继续。

#### 1.2 已知缺陷

1. **移动端是相对薄弱的一环**：2.2.7 已修复此前手机端打不开、一直转圈的问题（网关侧路径改写、清理历史 Service Worker、补移动端兼容层），桌面 Chrome / Edge / Firefox 以及移动视口已验证；但**真机鸿蒙与安卓飞牛 APP 内嵌 WebView 未做全机型覆盖**，个别机型仍可能出现界面错位、控件缺失或发消息无响应，请附机型与系统版本反馈。
2. **浏览器旧缓存会残留问题**：升级后若仍白屏 / 转圈，先「应用中心停用再启用」一次，再清一次该站点的浏览器缓存——旧的 Service Worker 可能还在接管页面。
3. **兼容补丁与上游页面结构耦合**：网关会在响应流里做入口前缀改写与兼容层注入，这部分依赖上游前端结构；**上游大改前端后可能出现局部错位、按钮失效或请求失败**，需要重新适配打包才能恢复。
4. **升级 / 重启会中断会话**：升级、停用启用都会重启服务，正在执行的 AI 任务会中断，长任务请等跑完再升级。
5. **低配机型会吃紧**：1GB 内存只是安装门槛，大仓库索引与长会话会明显占用内存与 CPU，低配 ARM 机型可能出现卡顿，极端情况下进程会被系统回收。

#### 1.3 使用风险

1. **AI 会真实修改你的文件**：项目目录内的文件可被读写、覆盖、删除，**没有回收站**。重要项目请用 Git 或外部备份，不要只依赖这一份。
2. **AI 会执行从网络下载的代码**：让它安装依赖、运行脚本时，实际执行的是远端拉下来的程序，存在供应链风险；**不要在项目目录里放密钥、证书、身份资料**。
3. **API Key 以明文存放在 NAS 上**：配置保存在应用数据目录（仅运行用户可读），但 NAS 被入侵或账号被盗即等同泄露。建议给 Key 设置额度上限并定期轮换。
4. **代码与对话会发往模型服务商**：使用云端模型时，项目代码与提示词会离开你的设备，是否合规取决于数据性质与服务商条款；敏感项目请改用本地模型。
5. **能登录飞牛账号就能用本应用**：应用侧没有二次鉴权，安全边界等于飞牛账号安全。对外暴露 NAS 时请使用强密码与二次验证。

#### 1.4 上游与版本风险

1. **版本跟随上游、存在时间差**：上游发版到应用中心推送之间会有滞后；急用新功能请等更新，**不要自行替换包内二进制**，替换后本应用不保证可用。
2. **上游可能改接口与配置格式**：升级后模型接口、配置项可能变化，历史配置不一定兼容，需要按上游文档重新调整。
3. **上游许可与条款可能变化**：本应用按当前上游 MIT 许可打包；若上游调整许可，后续版本会重新评估适配方式。
4. **第三方模型服务商不受控**：限流、封号、计费调整、接口下线均由服务商决定，与本应用及发布者无关。

### 3. 安装

- **方式一（推荐）**：飞牛应用中心搜索「OpenCode」直接安装。
- **方式二**：手动安装 `opencode_all_x.y.z.fpk`（应用中心 → 手动安装）。本仓库收录对应版本的源代码，可自行打包。

安装要求与说明：

1. 系统版本 ≥ 1.1.8（`os_min_version`）；架构需为 x86_64 或 aarch64（ARM64），其它架构安装前检查会直接拦下并提示。
2. 内存 ≥ 1GB（低于此值安装前检查会拦下）；推荐 2GB 以上，AI 会话与索引会占用较多内存。
3. 安装包约 **235MB**，装完程序文件约 **512MB**（两个架构的二进制都在包内）；项目文件占用取决于你放进去的代码量。
4. 安装过程**不联网、不拉镜像、不下依赖**，纯本地解包 + 权限初始化，通常 **20~60 秒**完成。
5. 安装向导只有「安装须知」和「安全说明」两页，**没有端口、目录之类的可填项**——路径固定，避免配错。

### 4. 访问与登录

- **唯一入口**：飞牛桌面 / 应用中心点击「OpenCode」，经统一网关进入 `/app/opencode`，**登录飞牛即完成鉴权**，应用内没有第二套账号密码。
- 不支持 `http://<NAS_IP>:端口` 这种直连方式：应用只监听一个 unix socket（`app.sock`），由飞牛网关代理，**没有任何对外 TCP 端口**。想换访问方式只能在应用中心换入口，不能改端口。
- 若点开是空白页或一直转圈：先在应用中心**停用再启用**一次；仍然异常时看「数据存放位置」里的 `main.log` / `gateway.log`。

### 5. 首次配置模型

1. 打开应用 → 右上角「+」新建会话（先「添加项目」选择项目文件夹）。
2. 按界面引导选择模型服务商并填写 API Key；或选择自定义 / 本地端点，填 `http://127.0.0.1:11434/v1`（Ollama）之类的地址。
3. 模型列表由上游的模型目录服务（models.dev）拉取，**需要 NAS 能出网**；纯内网环境请选本地端点，不要依赖在线目录。
4. 会话输入框那一排会显示「选择智能体 / 选择模型 / 推理强度 / 加号」等控件；装了多个模型时，带推理档位的模型排在前面，方便直接切换强度。

> 填错的 Key 不会导致应用崩溃，只会让该会话报鉴权错误；改完配置新建会话即可生效。

### 6. 数据存放位置

| 内容 | 位置（管理员视角查看） |
| --- | --- |
| 项目文件（你与 AI 共同编辑的代码、文档） | `文件管理 → 管理员视角 → 设备全部文件 → 存储空间1（按实际存储空间为准）→ @appdata → opencode → projects` |
| 应用数据（配置、API Key、会话记录） | 同上路径下的 `@appdata → opencode → oc_home` |
| 运行日志（安装 / 网关 / 服务 / 升级 / 卸载） | 同上路径下的 `@appdata → opencode → *.log`（`install.log`、`main.log`、`gateway.log`、`serve.log`、`upgrade.log`、`uninstall.log`） |

- 查看以上路径**需要管理员账号**（普通成员无「管理员视角」入口）。
- 项目目录安装时会自动建好 `我的项目` 子目录和一份 `使用说明.txt`，属主为本应用运行用户，AI 可直接读写。
- Windows 侧可用 SMB 进「应用文件 → opencode → projects」直接编辑项目文件，与 AI 改的是同一份。
- 应用自身的程序文件是只读安装，运行期只写应用数据目录与项目目录。

### 7. 端口与网络

| 项目 | 说明 |
| --- | --- |
| 对外监听端口 | **无**。应用不监听任何 TCP 端口，无法用 IP + 端口访问 |
| 内部服务端口 | `127.0.0.1:14096`，只绑回环，供本机网关代理，外部不可达 |
| 应用中心登记端口 | `4096`（仅应用中心登记与健康检查用，不对应真实监听） |
| 访问 socket | `<应用目录>/app.sock`（unix socket，由飞牛统一网关代理） |

- 出站访问：连接你所配置的模型服务商 API（如 `api.anthropic.com`、`api.openai.com`、`generativelanguage.googleapis.com`、`api.deepseek.com` 或你的自建端点），以及模型目录服务 `models.dev`。
- 上游的「远程 / 公网隧道」能力在本应用中**被钉死关闭**：安装时写入 `remote: false`，启动子进程时注入 `OPENCODE_DISABLE_REMOTE=1`，并在每次启动前做一次配置兜底。也就是说，这个应用不会自己把服务暴露到公网。

### 8. 升级与卸载

**升级**

- 应用中心收到新版后点更新即可；升级只替换程序文件并重启服务，**配置、API Key、会话记录、项目文件全部保留**。
- 升级期间正在跑的 AI 会话会中断，建议空闲时升级。
- 版本号跟随上游：上游发新版 → 本项目重新打包 → 应用中心推送。

**卸载**

- 卸载向导有两项选择，默认都是**保留**：
  - 应用数据（配置 / API Key / 会话）：保留 → 重装后无需重新配置；删除 → 清空 `@appdata/opencode`。
  - 项目文件：保留（推荐）→ 项目代码原样留在磁盘；删除 → 仅删除本应用登记的项目目录，其它目录不动。
- 不改向导直接卸载（例如命令行卸载）**一律保留**数据。
- 卸载会停掉网关与 `opencode serve` 进程、清理 socket 与 pid 文件，并回收运行用户对用户目录的访问授权（重装时自动重新授予）。

### 9. 权限与安全边界

1. **非 root 运行**：服务进程身份为 `opencode-agent`（应用包自带用户），对系统目录（`/etc`、`/usr`、飞牛系统配置等）无写权限。
2. **文件范围**：默认可读写的是应用数据区内的项目目录；项目目录之外的系统目录与其他用户数据无权限。
3. **AI 会真实执行命令**：这是产品能力本身，不是漏洞。它执行的每条命令都在上述权限边界内，但**删改你自己项目里的文件是能做的**。重要数据请自行备份，不要把这个应用指向含敏感数据的目录。
4. **无 root、无内核模块、无 Docker 依赖**：不装驱动、不改系统配置、不需要 Docker 权限。
5. **鉴权由飞牛门户承担**：应用侧不额外校验，因此**能登录你飞牛账号的人就能用这个应用**。多人共用 NAS 时请按飞牛的用户与权限体系管理账号。

### 10. 外网访问

需要在外网使用时，走飞牛官方远程访问 / 内网穿透，或你自己的 VPN。**不要**尝试给本应用映射端口——它没有对外端口可映射。也不要在无防护的情况下把 NAS 整体暴露到公网。

### 11. 常见问题

| 现象 | 处理 |
| --- | --- |
| 点开空白页 / 一直转圈 | 应用中心停用再启用一次；仍异常查看 `gateway.log` 与 `serve.log` |
| 页面能开，发消息报错 | 多为模型 Key、端点地址或 NAS 出网问题；换成本地端点验证一次 |
| 模型列表是空的 | 在线目录需要访问 `models.dev`；纯内网请用自定义 / 本地端点 |
| 手机（飞牛 APP）里打不开或控件缺失 | 先用手机浏览器访问同一入口验证；仍异常请附上手机型号与系统版本反馈 |
| 找不到项目文件 | 需管理员账号，按「数据存放位置」的路径在文件管理（管理员视角）查看 |
| 卸载后重装要重新配 Key | 卸载时选了「删除应用数据」；重装后重新填一次即可 |
| 磁盘占用变大 | 项目目录里的依赖、构建产物（`node_modules` 等）属正常占用，按需清理 |

### 12. 版本策略

- 版本号**跟随上游官方 Release**，格式 `x.y.z`。
- 若上游未发新版、仅因打包自身问题重发，用 `x.y.z-n`（如 `2.2.6-1`）。
- 包内上游二进制与上游 Releases 一一对应，不掺入任何第三方修改；飞牛适配改动全部在包外层（脚本 + Go 网关）。
